# SyncHub for macOS（菜单栏 App）

> **1.1.2 更新**：①「最近项目」里点文件直接打开：接收文件夹里已有同名同大小的副本（包括 `名称 (1).扩展名`）就直接打开，没有才下载后打开，菜单上会标「已在本机」；按住 **⌥** 改为「在 Finder 中显示」，按住 **⌘** 改为「仅下载」（已在本机时为「复制文件路径」）。② 文字条目：点一下仍然是复制；按住 ⌥ 点开「查看全文」小窗口，可选中、可「复制全部」；按住 ⌘ 在网页中查看。③ 点通知：收到 / 下载文件的通知点开就是用默认应用打开这个文件（没有能打开的应用、脚本类文件或文件已被移走时，改为在 Finder 中显示）；其他通知点开会弹出 SyncHub 菜单。④ 修复点通知没反应：1.1.1 只在启动时查询一次通知权限，权限还没确认（或之后才在系统设置里允许）时，所有通知都改由 `osascript` 发出，这类通知属于「脚本编辑器」，点了不会回到 SyncHub；现在每次发通知前都会重新确认权限，并且在 App 启动完成前就注册好通知回调。

> **1.1.1 更新**：①「最近项目」改为置顶 → 收藏 → 最新的顺序，去掉条目前的类型图标；② 菜单里新增服务器存储一行；③ 修复：收到别的设备复制的内容后，Mac 有时会把同一条内容立刻再上传一次（回传）。现在会记住服务器当前的内容，和它相同的本地复制不再上传；同时只允许运行一个 SyncHub，防止两个副本互相回传。

和 Windows 端、Android 端、网页版配合使用的 Mac 客户端：常驻菜单栏，**自动双向同步剪贴板**，自动接收其他设备发来的文件，可以从 Finder 右键、菜单栏图标、剪贴板或「服务」菜单发送。界面跟网页版一样，是浅色扁平风格，强调色为 macOS 蓝。

> 服务器和接口都没改：文件用现有的 `/api/hub/*` 接口，剪贴板用 SyncClipboard 官方协议（`/SyncClipboard.json`、`/file/…`），和 Windows 官方客户端、Android App 完全一样。脚本和代码里没有写死任何账号密码，密码只保存在 Mac 的「钥匙串」中。

## 功能

| 功能 | 说明 |
|---|---|
| 剪贴板同步 | 在 Mac 上复制文字，Windows 和手机上马上能粘贴；在其他设备上复制，Mac 上也能直接 ⌘V。图片和截图也会同步（可在设置里关掉）。详见下面的「剪贴板同步」 |
| 菜单栏图标 ⇅ | 第一行显示连接状态（绿点表示已连接）、上次同步时间和自动接收开关；下面一行灰色小字是服务器存储，例如「存储 已用 10.6 GB / 58.9 GB · 剩余 45.3 GB」（打开菜单时后台刷新，最多 30 秒一次；用量超过 85% 变橙色，超过 95% 变红色）。发送文件时图标旁会显示总进度百分比 |
| 最近项目 | 列出云端 8 条：置顶的在最前，然后是收藏的，其余按时间从新到旧（和网页版、Android 一样）；条目前面不再显示类型图标，显示来源设备、大小、多久之前发送，快到期的会提示剩余时间。**点文字**复制到剪贴板，**点文件**直接打开（本机没有时先下载到接收文件夹）；按住 **⌥** 时，文件改为「在 Finder 中显示」，文字改为「查看全文」；按住 **⌘** 时，文件改为「仅下载」，文字改为「在网页中查看」 |
| 发送文件… (⌘O) | 可多选，文件夹会自动压缩成 zip 再发 |
| 拖到图标上发送 | 把文件直接拖到菜单栏图标上松开即可 |
| 发送剪贴板 (⇧⌘V) | 剪贴板里是文件就上传文件；是截图或图片就转成 PNG 上传；是文字就发送文字，同时更新各设备共享的剪贴板 |
| 发送进度窗口 | 白底窗口，每个文件一行，显示进度条、速度和剩余时间，可以取消或重试。全部成功后 1.5 秒自动关闭（鼠标停在窗口上时不关），点「后台发送」可以先把窗口收起来 |
| 自动接收 | 逻辑和 Windows 端一样：每 3 秒检查一次，记住上次处理到的编号，不会重复下载；同名同大小的文件跳过，同名不同大小的存成 `名称 (1).扩展名`；下载时先写 `.downloading` 临时文件，完成后再改名。收到文件会弹出系统通知，点通知会用默认应用打开这个文件（打不开时在 Finder 中定位） |
| Finder 右键 | 快速操作 →「发送到跨端传输中心」，文件会交给 App 并显示进度窗口 |
| 服务菜单 | 在任意 App 里选中文字，右键或应用菜单 → 服务 →「发送到 SyncHub」 |
| 设置 (⌘,) | 服务器地址（默认 `https://020814.xyz`）、用户名、密码（存在钥匙串里）、接收文件夹（默认 `~/Desktop/跨端传输文件`）、登录时启动、通知开关，还有「测试连接」按钮 |
| 登录时启动 | macOS 13 及以上用系统登录项（SMAppService）；macOS 12 用 LaunchAgent 代替 |
| URL Scheme | `synchub://send?path=/文件路径`、`synchub://clipboard`、`synchub://settings`、`synchub://web`，可以接到快捷指令或脚本里 |

## 剪贴板同步

默认开启。菜单栏图标 →「同步剪贴板」可以随时开关，下面一行灰色小字显示最近一次同步，比如「14:03:21 ↑ 已发送文字（23 字）」或「↓ 已收到图片（1.2 MB）」，出错时变成红字。设置里还可以单独关掉「同时同步图片和截图」。

工作方式：
- **Mac → 其他设备**：每 0.7 秒看一下剪贴板有没有变化（只看系统的变化计数，不读内容），变了才读取，把文字上传到服务器的 `SyncClipboard.json`。Windows 上的 SyncClipboard 和手机上的 SyncHub 会自动取到。
- **其他设备 → Mac**：每 1.5 秒检查一次服务器，有新内容就写进 Mac 剪贴板，直接 ⌘V 即可。
- **不会来回弹**：App 记得「当前剪贴板里已经同步过的内容」。自己写进去的内容不会再传回服务器，自己刚传上去的内容也不会再写回来；但重新复制一段之前复制过的文字（A → B → A）仍然会正常同步。
- **第一次启动不会覆盖**：开启后的第一次检查只记下服务器当前的内容，不会把 Mac 剪贴板替换掉；Mac 上原来的剪贴板也不会被自动上传，之后新复制的才会同步。换服务器或账号时同样重新开始。
- **不同步的内容**：
  - 密码管理器复制的密码。1Password 这类遵守 nspasteboard.org 约定的 App，复制密码时会给剪贴板打上「隐藏/临时」标记（`org.nspasteboard.ConcealedType`、`TransientType`、`AutoGeneratedType`），带这些标记的内容一律跳过。不打标记的密码管理器没法识别，复制的密码会像普通文字一样同步。
  - 超过 500 KB 的文字，会跳过并在菜单里提示。超过 10240 个字符、但没超过 500 KB 的长文字会照常同步，按官方客户端的方式作为 `Text_….txt` 附件上传。
  - 超过 20 MB 的图片。
  - 在 Finder 里复制的文件。发文件请用「发送文件…」、拖到图标上或 Finder 右键。其他设备发来的文件仍由「自动接收」保存到接收文件夹。
- **断网不会停**：连不上服务器时会自动放慢重试（2 秒、4 秒……最长 30 秒一次），恢复后马上回到正常速度。断网时复制的内容，恢复后会补传。从睡眠唤醒后也会自动重新开始。

**权限**：读写剪贴板不需要在「系统设置」里授权。目前正式版 macOS（12 到 26）默认不会弹窗。Apple 在 macOS 15.4 里预告过一个「粘贴板隐私」功能：App 在用户没有按粘贴时读取剪贴板，系统会弹窗询问。目前这个功能只是开发者预览，正式版默认没有打开。如果以后的 macOS 打开了它，看到「SyncHub 正在尝试访问粘贴板」时请选允许，并在「系统设置 → 隐私与安全性」里把 SyncHub 设成始终允许，否则 Mac → 其他设备方向会失效。

**简易模式**（没有菜单栏 App 时）不支持剪贴板同步。

## 安装

需要 **macOS 12 或更高版本**，以及 Xcode 命令行工具（约 1 GB，不需要装完整的 Xcode）。

1. 把整个 `03_macOS自动接收与Finder右键套件` 文件夹拷到 Mac 上，比如放到「下载」里。
2. 打开「终端」，执行：
   ```bash
   cd ~/Downloads/03_macOS自动接收与Finder右键套件
   bash install_mac_synchub.sh
   ```
3. 如果还没装命令行工具，会弹出系统安装窗口。点「安装」，装完回到终端按回车继续。
4. 脚本会自动编译出 `~/Applications/SyncHub.app`（大约 1 分钟），停掉旧版后台接收，装好 Finder 右键菜单，然后启动 App。
5. 第一次启动会打开设置窗口。确认服务器地址，服务器要求登录时再填用户名和密码，点「测试连接」→「保存」。系统询问是否允许通知时，点「允许」（不允许的话通知只能看、点了没反应；之后可在「系统设置 → 通知 → SyncHub 跨端传输」里打开）。
6. 「服务」菜单里的「发送到 SyncHub」如果没有出现，到「系统设置 → 键盘 → 键盘快捷键 → 服务 → 文本」里勾上。

从旧版升级时，安装程序会：
- 停用并删除旧的 LaunchAgent `xyz.020814.synchub`，这样不会出现两个程序同时下载。App 会接着读取旧版的 `~/.synchub/last_id.txt`，已经收过的文件不会再下载一遍。
- 删除旧的「📲 发送到跨端传输 (Windows与手机)」快速操作，换成「发送到跨端传输中心」，右键菜单里不会出现两个。
- 如果桌面上的「跨端传输文件」是旧版建的链接（指向 `~/Downloads/跨端传输文件`），会继续沿用，文件仍然存在原来的位置。

### 简易模式（兜底）

编译失败、不想装命令行工具，或者系统低于 macOS 12 时，会自动改用简易模式，也可以手动运行 `bash install_mac_synchub.sh --legacy`：
- 后台接收用的是系统自带的 JavaScript for Automation（`osascript`），不需要 Python 或 Xcode。逻辑和 App 一样，也会弹通知。
- Finder 右键发送用 `curl` 流式上传，没有进度窗口，只在开始和结束时各弹一次通知。
- 账号密码可以在安装时输入，密码存进钥匙串。
- 之后装好命令行工具，再运行一次 `bash install_mac_synchub.sh` 就会升级成菜单栏 App，并自动停掉简易模式的后台服务。

## 卸载

```bash
bash uninstall_mac_synchub.sh                  # 全部移除，包括钥匙串里的密码
bash uninstall_mac_synchub.sh --keep-settings  # 保留设置和密码
```
已经收到的文件不会被删除。

## 常见问题

- **重新安装后，系统提示「SyncHub 想要使用钥匙串中的机密信息」**：App 是本机签名（ad-hoc）的，每次重新编译签名都会变，点「始终允许」就行。
- **菜单栏里看不到图标**：菜单栏图标太多时会被刘海或其他图标挡住，可以按住 ⌘ 拖动调整位置，或者先退出几个菜单栏 App。
- **收不到文件**：打开菜单看第一行的状态。红点表示连接失败，后面会写原因，比如用户名或密码不对、网络错误。到「设置 → 测试连接」检查一下。
- **剪贴板不同步**：先看菜单里「同步剪贴板」有没有打勾，再看它下面那行小字。红字通常是用户名或密码不对，或者网络连不上。手机端要在系统设置里把 SyncHub 的剪贴板权限设成「始终允许」（realme、OPPO、一加手机尤其要注意）。Windows 端要确认 SyncClipboard 正在运行，并且开着自动同步。
- **复制的密码没有同步**：这是有意设计的，见上面的「不同步的内容」。
- **想换接收文件夹**：在「设置 → 保存到 → 更改…」里选新的位置。

## 开发者备注

- 手动编译：`bash SyncHubMac/build_app.sh ~/Applications`。也可以在 `SyncHubMac/` 里执行 `swift build -c release`，或者直接用 Xcode 打开 `Package.swift`。
- 接口层测试（不连生产服务器）：先用 `test/run_local.py` 在本机起一个 `synchub_server.py`，然后执行：
  ```bash
  swiftc SyncHubMac/Sources/SyncHub/HubCore.swift SyncHubMac/Tests/LinuxHarness/main.swift -o harness
  ./harness http://127.0.0.1:<端口> /tmp/harness_work
  ```
- 剪贴板逻辑测试（不连生产服务器）：
  ```bash
  cd SyncHubMac/Tests/ClipHarness
  swiftc -O ../../Sources/SyncHub/HubCore.swift ../../Sources/SyncHub/ClipSyncCore.swift main.swift -o clipharness
  python3 mock_syncclipboard_server.py 15090 tester test-only &   # 本地模拟服务器，账号密码随便填
  ./clipharness http://127.0.0.1:15090 tester test-only
  ```
- 网页侧边栏里「Mac 自动接收套件」下载的仍然是服务端内置的旧版脚本，因为服务端没有改动。要装菜单栏 App，请用这个文件夹里的安装脚本。
